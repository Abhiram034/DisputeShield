# Demo flow

1. Open the prevention overview and highlight that cases are created from post-payment events, before a dispute exists.
2. Open the delivery-delay case and review order SLA, support contact, and recommended delivery update.
3. Show a duplicate-looking payment: two close charges are candidates; differing session IDs mean no automatic refund.
4. Show the unusual-device/high-value case. It is always flagged for human review and never gets a normal customer message.
5. Show approval, policy version capture, idempotency and audit events, then explain that outcomes are observed over time.
6. Export the case queue as CSV.

All displayed records are synthetic. Dashboard actions are local demo state only.
